A cheap judge reads every candidate. Code decides what Claude sees.

HCES sits in front of ICM's large reference files. It retrieves candidate passages, has JEV answer typed questions about each one, and fills a fixed token budget with whole passages, keeping a record of every keep and cut.

        Data model

        Six records, none ever overwritten

        Units are written once to the knowledge base. Everything a run produces goes into an insert-only results store, so a rerun adds rows and never overwrites them.

        Judge interface

        One interface, any judge

        JEV is the first implementation. A local model can be added later behind the same four members without touching retrieval, rollup or the store.

        # hces/judge.py
judge(task, rubric, units)    -> judgments
answerable(task, kept_units) -> probability
estimate_cost(task, rubric, units) -> dollars
model_id

# hces/embed.py (same idea, for the bake-off)
embed(texts) -> vectors
model_id

        One request per unit: the state holds the task and the unit's text, the questions are the rubric's. Failed requests are retried, then recorded as failed, never skipped. Open: whether the SDK can judge several units in one request.

        Rollup and budget fill, all in code

        Six rules, applied in order

        1. Unit scoreWeighted mean of its Score answers, scaled 0 to 1.
        2. Critical keepA critical Noul question past its cutoff keeps the unit whatever its score.
        3. Parent scoreBest child score plus the count of children that passed.
        4. Budget fillSort by critical, then score, then retrieval rank. Add whole units until 6,000 tokens.
        5. Unsure bandUnits just under the cutoff are kept if budget remains. Recall first.
        6. Not in the documentsIf nothing passes, or answerability is too low, the gate says so instead of padding.

        Store, indexes and setup

        Results store

        • hces/data/results.db, SQLite
        • Tables: rubrics, runs, judgments, decisions
        • Triggers abort any UPDATE or DELETE; a unit test proves it
        • A rerun gets a new run ID

        Indexes

        • One file per volume: kb/index/<slug>.db
        • sqlite-vec, 384-dimension bge-small vectors
        • FTS5 keyword table beside it
        • Hybrid merge by reciprocal rank fusion
